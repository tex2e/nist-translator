[要約] SP 800-145 は、クラウドコンピューティングについての NIST の定義を示す文書です。定義は、5つの基本特性、3つのサービスモデル、4つの導入モデルで構成され、サービスモデルと導入モデルは単純な分類体系を成すとされています。クラウドサービスと導入戦略を幅広く比較する手段となり、クラウドコンピューティングとは何かからどう利用するのが最善かに至る議論のベースラインを提供することを意図しています。

1.2 Purpose and Scope

原本 PDF p.5

1.2 目的と適用範囲

Cloud computing is an evolving paradigm. The NIST definition characterizes important aspects of cloud computing and is intended to serve as a means for broad comparisons of cloud services and deployment strategies, and to provide a baseline for discussion from what is cloud computing to how to best use cloud computing. The service and deployment models defined form a simple taxonomy that is not intended to prescribe or constrain any particular method of deployment, service delivery, or business operation.

原本 PDF p.5

クラウドコンピューティングは進化を続けるパラダイムである。NISTの定義は、クラウドコンピューティングの重要な側面を特徴付けるものであり、クラウドサービスおよび導入戦略を幅広く比較するための手段となること、ならびに、クラウドコンピューティングとは何かから、クラウドコンピューティングをどのように利用するのが最善かに至るまでの議論のベースラインを提供することを意図している。ここで定義するサービスモデルと導入モデルは単純な分類体系を成すものであり、特定の導入方法、サービス提供方法、または事業運営方法を規定したり制約したりすることを意図したものではない。

2. The NIST Definition of Cloud Computing

原本 PDF p.6

2. NISTによるクラウドコンピューティングの定義

Cloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (e.g., networks, servers, storage, applications, and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction. This cloud model is composed of five essential characteristics, three service models, and four deployment models.

原本 PDF p.6

クラウドコンピューティングとは、構成可能なコンピューティング資源（例えば、ネットワーク、サーバー、ストレージ、アプリケーション、サービス）の共有プールに対する、ユビキタスで便利なオンデマンドのネットワークアクセスを可能にするモデルであり、それらの資源は最小限の管理作業またはサービス提供者とのやり取りで迅速にプロビジョニングおよび解放できる。このクラウドモデルは、5つの基本特性、3つのサービスモデル、4つの導入モデルで構成される。

Essential Characteristics:

原本 PDF p.6

基本特性：

On-demand self-service. A consumer can unilaterally provision computing capabilities, such as server time and network storage, as needed automatically without requiring human interaction with each service provider.

原本 PDF p.6

オンデマンド・セルフサービス。利用者は、サーバー時間やネットワークストレージなどのコンピューティング能力を、各サービス提供者との人手によるやり取りを必要とせずに、必要に応じて一方的かつ自動的にプロビジョニングできる。

Broad network access. Capabilities are available over the network and accessed through standard mechanisms that promote use by heterogeneous thin or thick client platforms (e.g., mobile phones, tablets, laptops, and workstations).

原本 PDF p.6

幅広いネットワークアクセス。能力はネットワーク経由で利用可能であり、異種のシンクライアントまたはシッククライアントのプラットフォーム（例えば携帯電話、タブレット、ノートパソコン、ワークステーション）による利用を促進する標準的な仕組みを通じてアクセスされる。

Resource pooling. The provider’s computing resources are pooled to serve multiple consumers using a multi-tenant model, with different physical and virtual resources dynamically assigned and reassigned according to consumer demand. There is a sense of location independence in that the customer generally has no control or knowledge over the exact location of the provided resources but may be able to specify location at a higher level of abstraction (e.g., country, state, or datacenter). Examples of resources include storage, processing, memory, and network bandwidth.

原本 PDF p.6

リソースプーリング。提供者のコンピューティング資源は、マルチテナントモデルを用いて複数の利用者に提供するためにプールされ、さまざまな物理資源および仮想資源が利用者の需要に応じて動的に割り当てられ、再割り当てされる。顧客は一般に、提供される資源の正確な所在を制御することも知ることもできないが、より高い抽象度（例えば国、州、データセンター）で所在を指定できる場合があるという点で、所在に依存しないという感覚がある。資源の例には、ストレージ、処理、メモリ、ネットワーク帯域幅がある。

Rapid elasticity. Capabilities can be elastically provisioned and released, in some cases automatically, to scale rapidly outward and inward commensurate with demand. To the consumer, the capabilities available for provisioning often appear to be unlimited and can be appropriated in any quantity at any time.

原本 PDF p.6

迅速な弾力性。能力は弾力的に、場合によっては自動的にプロビジョニングおよび解放でき、需要に応じて迅速にスケールアウトおよびスケールインできる。利用者から見ると、プロビジョニング可能な能力は無制限であるように見えることが多く、いつでも任意の量を取得できる。

Measured service. Cloud systems automatically control and optimize resource use by leveraging a metering capability1 at some level of abstraction appropriate to the type of service (e.g., storage, processing, bandwidth, and active user accounts). Resource usage can be monitored, controlled, and reported, providing transparency for both the provider and consumer of the utilized service.

原本 PDF p.6

測定可能なサービス。クラウドシステムは、サービスの種類（例えばストレージ、処理、帯域幅、アクティブな利用者アカウント）に適した抽象度で計測機能1を活用し、資源の使用を自動的に制御し、最適化する。資源の使用状況は監視、制御、報告でき、利用されるサービスの提供者と利用者の双方に透明性を提供する。

Service Models:

原本 PDF p.6

サービスモデル：

Software as a Service (SaaS). The capability provided to the consumer is to use the provider’s applications running on a cloud infrastructure2. The applications are accessible from various client devices through either a thin client interface, such as a web browser (e.g., web-based email), or a program interface. The consumer does not manage or control the underlying cloud infrastructure including network, servers, operating systems, storage, or even individual application capabilities, with the possible exception of limited user-specific application configuration settings.

原本 PDF p.6

サービスとしてのソフトウェア（SaaS）。利用者に提供される能力は、クラウドインフラストラクチャ2上で稼働する提供者のアプリケーションを利用することである。アプリケーションには、ウェブブラウザーなどのシンクライアントインターフェース（例えばウェブメール）またはプログラムインターフェースを通じて、さまざまなクライアント端末からアクセスできる。利用者は、ネットワーク、サーバー、オペレーティングシステム、ストレージを含む基盤となるクラウドインフラストラクチャを管理も制御もせず、個々のアプリケーション機能さえも管理も制御もしない。ただし、限定的な利用者固有のアプリケーション構成設定は例外となり得る。

Platform as a Service (PaaS). The capability provided to the consumer is to deploy onto the cloud infrastructure consumer-created or acquired applications created using programming languages, libraries, services, and tools supported by the provider.3 The consumer does not manage or control the underlying cloud infrastructure including network, servers, operating systems, or storage, but has control over the deployed applications and possibly configuration settings for the application-hosting environment.

原本 PDF p.6

サービスとしてのプラットフォーム（PaaS）。利用者に提供される機能は、提供者がサポートするプログラミング言語、ライブラリ、サービス、ツールを使って作成された、利用者が作成または取得したアプリケーションを、クラウドインフラストラクチャに展開することである。3利用者は、ネットワーク、サーバー、オペレーティングシステム、ストレージを含む基盤となるクラウドインフラストラクチャを管理・制御しないが、展開したアプリケーションを制御し、場合によってはアプリケーションのホスティング環境の構成設定も制御する。

1 Typically this is done on a pay-per-use or charge-per-use basis.
原本 PDF p.6
1 通常、従量課金または使用量に応じた課金方式で行われる。
2 A cloud infrastructure is the collection of hardware and software that enables the five essential characteristics of cloud computing. The cloud infrastructure can be viewed as containing both a physical layer and an abstraction layer. The physical layer consists of the hardware resources that are necessary to support the cloud services being provided, and typically includes server, storage and network components. The abstraction layer consists of the software deployed across the physical layer, which manifests the essential cloud characteristics. Conceptually the abstraction layer sits above the physical layer.
原本 PDF p.6
2 クラウドインフラストラクチャとは、クラウドコンピューティングの5つの基本特性を実現するハードウェアとソフトウェアの集合である。クラウドインフラストラクチャは、物理層と抽象化層で構成されると考えることができる。物理層は、提供するクラウドサービスを支えるために必要なハードウェア資源で構成され、通常はサーバー、ストレージ、ネットワークの各コンポーネントを含む。抽象化層は、物理層全体に展開されたソフトウェアで構成され、クラウドの基本特性を実現する。概念上、抽象化層は物理層の上位に位置する。

Infrastructure as a Service (IaaS). The capability provided to the consumer is to provision processing, storage, networks, and other fundamental computing resources where the consumer is able to deploy and run arbitrary software, which can include operating systems and applications. The consumer does not manage or control the underlying cloud infrastructure but has control over operating systems, storage, and deployed applications; and possibly limited control of select networking components (e.g., host firewalls).

原本 PDF p.7

サービスとしてのインフラストラクチャ（IaaS）。利用者に提供される機能は、処理能力、ストレージ、ネットワーク、その他の基本的なコンピューティング資源を確保することであり、利用者はそこに任意のソフトウェア（オペレーティングシステムやアプリケーションを含み得る）を展開して実行できる。利用者は基盤となるクラウドインフラストラクチャを管理・制御しないが、オペレーティングシステム、ストレージ、展開したアプリケーションを制御する。また、一部のネットワークコンポーネント（例えばホストファイアウォール）を限定的に制御できる場合がある。

Deployment Models:

原本 PDF p.7

導入モデル：

Private cloud. The cloud infrastructure is provisioned for exclusive use by a single organization comprising multiple consumers (e.g., business units). It may be owned, managed, and operated by the organization, a third party, or some combination of them, and it may exist on or off premises.

原本 PDF p.7

プライベートクラウド。クラウドインフラストラクチャは、複数の利用者（例えば事業部門）で構成される単一の組織が専用で使用するために提供される。その組織、第三者、またはそれらの組み合わせによって所有、管理、運用される場合があり、オンプレミスにもオフプレミスにも存在し得る。

Community cloud. The cloud infrastructure is provisioned for exclusive use by a specific community of consumers from organizations that have shared concerns (e.g., mission, security requirements, policy, and compliance considerations). It may be owned, managed, and operated by one or more of the organizations in the community, a third party, or some combination of them, and it may exist on or off premises.

原本 PDF p.7

コミュニティクラウド。クラウドインフラストラクチャは、共通の関心事（例えば使命、セキュリティ要件、ポリシー、コンプライアンス上の考慮事項）を持つ組織に属する利用者からなる特定のコミュニティが専用で使用するために提供される。コミュニティに属する1つ以上の組織、第三者、またはそれらの組み合わせによって所有、管理、運用される場合があり、オンプレミスにもオフプレミスにも存在し得る。

Public cloud. The cloud infrastructure is provisioned for open use by the general public. It may be owned, managed, and operated by a business, academic, or government organization, or some combination of them. It exists on the premises of the cloud provider.

原本 PDF p.7

パブリッククラウド。クラウドインフラストラクチャは、一般公衆が自由に利用できるように提供される。企業、学術機関、政府機関、またはそれらの組み合わせによって所有、管理、運用される場合がある。クラウド提供者の施設内に存在する。

Hybrid cloud. The cloud infrastructure is a composition of two or more distinct cloud infrastructures (private, community, or public) that remain unique entities, but are bound together by standardized or proprietary technology that enables data and application portability (e.g., cloud bursting for load balancing between clouds).

原本 PDF p.7

ハイブリッドクラウド。プライベート、コミュニティ、パブリックのうち2つ以上の異なるクラウドインフラストラクチャを組み合わせたもので、各インフラストラクチャは独立した実体として保たれるが、標準技術または独自技術で結合され、データやアプリケーションの移植性を可能にする（例えば、クラウド間の負荷分散のためのクラウドバースティング）。

3 This capability does not necessarily preclude the use of compatible programming languages, libraries, services, and tools from other sources.
