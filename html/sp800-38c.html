Abstract

概要

未レビュー訳

This Recommendation defines a mode of operation, called CCM, for a symmetric key block cipher algorithm. CCM may be used to provide assurance of the confidentiality and the authenticity of computer data by combining the techniques of the Counter (CTR) mode and the Cipher Block Chaining-Message Authentication Code (CBC-MAC) algorithm.

原本 PDF p.5

本勧告は、対称鍵ブロック暗号アルゴリズムの動作モードとしてCCMと呼ばれる方式を定義する。CCMは、カウンター（CTR）モードと暗号ブロック連鎖メッセージ認証コード（CBC-MAC）アルゴリズムの技法を組み合わせることで、コンピューター・データの機密性と真正性を保証するために使用できる（may）。

3 Introduction

原本 PDF p.7

3 はじめに

未レビュー訳

This Recommendation specifies an algorithm, Counter with Cipher Block Chaining-Message Authentication Code [1], abbreviated CCM, that can provide assurance of the confidentiality and authenticity of data. CCM is based on an approved symmetric key block cipher algorithm whose block size is 128 bits, such as the Advanced Encryption Standard (AES) algorithm currently specified in Federal Information Processing Standard (FIPS) Pub. 197 [2]; thus, CCM cannot be used with the Triple Data Encryption Algorithm [3], whose block size is 64 bits. CCM can be considered a mode of operation of the block cipher algorithm. As with other modes of operation, a single key to the block cipher must be established beforehand among the parties to the data; thus, CCM should be implemented within a well-designed key management structure. The security properties of CCM depend, at a minimum, on the secrecy of the key.

原本 PDF p.7

本勧告は、データの機密性と真正性を保証できるアルゴリズムであるCounter with Cipher Block Chaining-Message Authentication Code [1]（略称CCM）を規定する。CCMは、ブロック長が128ビットの承認済み対称鍵ブロック暗号アルゴリズムに基づく。例えば、現在Federal Information Processing Standard (FIPS) Pub. 197 [2]で規定されているAdvanced Encryption Standard (AES)アルゴリズムがある。したがって、ブロック長が64ビットのTriple Data Encryption Algorithm [3]にはCCMを使用できない。CCMはブロック暗号アルゴリズムの動作モードとみなすことができる。他の動作モードと同様に、データの関係者間で事前にブロック暗号用の単一鍵を確立しなければならない。したがって、CCMは適切に設計された鍵管理構造の中で実装すべきである。CCMのセキュリティ特性は、少なくとも鍵の秘密性に依存する。（can）（cannot）（must）（should） (can)

未レビュー訳

CCM is intended for use in a packet environment, i.e., when all of the data is available in storage before CCM is applied; CCM is not designed to support partial processing or stream processing. The input to CCM includes three elements: 1) data that will be both authenticated and encrypted, called the payload; 2) associated data, e.g., a header, that will be authenticated but not encrypted; and 3) a unique value, called a nonce, that is assigned to the payload and the associated data.

原本 PDF p.8

CCMはパケット環境、すなわちCCMを適用する前にすべてのデータが記憶領域にそろっている状況での使用を意図している。CCMは部分処理やストリーム処理を支援するよう設計されていない。CCMへの入力は3つの要素からなる。1) 認証と暗号化の両方を行うデータ（ペイロードと呼ぶ）、2) ヘッダーなど、認証は行うが暗号化しない関連データ、3) ペイロードおよび関連データに割り当てる一意の値（ノンスと呼ぶ）。 (will) (will)

未レビュー訳

CCM consists of two related processes: generation-encryption and decryption-verification, which combine two cryptographic primitives: counter mode encryption and cipher block chaining-based authentication. Only the forward cipher function of the block cipher algorithm is used within these primitives.

原本 PDF p.8

CCMは、生成・暗号化と復号・検証という関連する2つのプロセスからなり、カウンター・モード暗号化と暗号ブロック連鎖に基づく認証という2つの暗号プリミティブを組み合わせる。これらのプリミティブ内では、ブロック暗号アルゴリズムの順方向暗号関数のみを使用する。

未レビュー訳

In generation-encryption, cipher block chaining is applied to the payload, the associated data, and the nonce to generate a message authentication code (MAC); then, counter mode encryption is applied to the MAC and the payload to transform them into an unreadable form, called the ciphertext. Thus, CCM generation-encryption expands the size of the payload by the size of the MAC. In decryption-verification, counter mode decryption is applied to the purported ciphertext to recover the MAC and the corresponding payload; then, cipher block chaining is applied to the payload, the received associated data, and the received nonce to verify the correctness of the MAC. Successful verification provides assurance that the payload and the associated data originated from a source with access to the key.

原本 PDF p.8

生成・暗号化では、暗号ブロック連鎖をペイロード、関連データ、ノンスに適用してメッセージ認証コード（MAC）を生成する。次に、カウンター・モード暗号化をMACとペイロードに適用し、暗号文と呼ばれる判読不能な形式に変換する。したがって、CCMによる生成・暗号化では、MACの長さ分だけペイロードのサイズが増える。復号・検証では、暗号文とされるデータにカウンター・モード復号を適用し、MACと対応するペイロードを復元する。次に、ペイロード、受信した関連データ、受信したノンスに暗号ブロック連鎖を適用して、MACの正しさを検証する。検証に成功すると、ペイロードと関連データが鍵へのアクセス権を持つ送信元に由来することが保証される。

未レビュー訳

A MAC provides stronger assurance of authenticity than a checksum or an error detecting code. The verification of a (non-cryptographic) checksum or an error detecting code is designed to detect only accidental modifications of the data, while the verification of a MAC, as occurs in CCM, is designed to detect intentional, unauthorized modifications of the data, as well as accidental modifications.

原本 PDF p.8

MACは、チェックサムや誤り検出符号より強い真正性保証を提供する。チェックサム（非暗号学的）または誤り検出符号の検証は、データの偶発的な変更のみを検出するよう設計されている。一方、CCMで用いられるMACの検証は、データの意図的かつ未認可の変更と偶発的な変更の両方を検出するよう設計されている。

未レビュー訳

This specification of CCM is intended to be compatible with the use of CCM within the draft amendment [4] to the IEEE Standard 802.11 for wireless local area networks [5].

原本 PDF p.8

このCCM仕様は、改訂案[4]（無線ローカル・エリア・ネットワーク向けIEEE Standard 802.11 [5]）内でCCMを使用する場合との互換性を意図している。

The underlying block cipher algorithm shall be approved, and a secret key for the block cipher algorithm shall be generated uniformly at random, or close to uniformly at random, i.e., so that each possible key is (nearly) equally likely to be generated. 5.2 Cryptographic Primitives

原本 PDF p.13

5.2 暗号プリミティブ

未レビュー訳

The CCM specification essentially combines two cryptographic mechanisms that are based on the forward cipher function. One mechanism is the Counter (CTR) mode for confidentiality, which is specified for general use in the first Part of this Recommendation [6]. The CTR mode requires the generation of a sufficiently long sequence of blocks called the counter blocks. The counter blocks must be distinct within a single invocation and across all other invocations of the CTR mode under any given key, but they need not be secret. This requirement on the counter blocks extends to the CCM mode. See [6] for further discussion of the generation of counter blocks; see Section 5.4 below for an additional requirement on the counter blocks in CCM.

原本 PDF p.13

CCM仕様は、基本的に順方向暗号関数に基づく2つの暗号機構を組み合わせる。一方は機密性を提供するカウンター（CTR）モードであり、本勧告の第1部[6]で一般用途向けに規定されている。CTRモードでは、カウンター・ブロックと呼ばれる十分に長いブロック列を生成する必要がある。カウンター・ブロックは、単一の呼出し内および所与の鍵の下での他のすべてのCTRモード呼出し間で互いに異ならなければならないが、秘密である必要はない。このカウンター・ブロックに関する要件はCCMモードにも適用される。カウンター・ブロックの生成に関する詳細は[6]を参照し、CCMのカウンター・ブロックに対する追加要件については以下の5.4節を参照する。 (must)

未レビュー訳

The other cryptographic mechanism within CCM is an adaptation of the cipher block chaining (CBC) technique from [6] to provide assurance of authenticity. Specifically, the CBC technique with an initialization vector of zero is applied to the data to be authenticated; the final block of the resulting CBC output, possibly truncated, serves as a message authentication code (MAC) of the data. The algorithm for generating a MAC in this fashion is commonly called CBC-MAC. This Recommendation does not approve CBC-MAC as an authentication mode outside of the context of the CCM specification; however, a variation of CBC-MAC is proposed for general use in the second Part of this Recommendation [7].

原本 PDF p.13

CCMにおけるもう一つの暗号機構は、真正性を保証するために[6]の暗号ブロック連鎖（CBC）技法を適用したものである。具体的には、認証対象データに対し、初期化ベクトルをゼロとしてCBC技法を適用する。得られるCBC出力の最終ブロックは、場合によっては切り詰められ、データのメッセージ認証コード（MAC）として機能する。この方法でMACを生成するアルゴリズムは、一般にCBC-MACと呼ばれる。本勧告は、CCM仕様の範囲外でCBC-MACを認証モードとして承認しない。ただし、CBC-MACの変形方式は、本勧告の第2部[7]で一般用途向けに提案されている。
