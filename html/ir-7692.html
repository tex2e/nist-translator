Abstract

原本 PDF p.4

概要

This report defines version 2.0 of the Open Checklist Interactive Language (OCIL). The intent of OCIL is to provide a standardized basis for expressing questionnaires and related information, such as answers to questions and final questionnaire results, so that the questionnaires can use a standardized, machine-readable approach to interacting with humans and using information stored during previous data collection efforts. OCIL documents are Extensible Markup Language (XML) based. This report defines and explains the requirements that IT products and OCIL documents asserting conformance with the OCIL 2.0 specification must meet.

原本 PDF p.4

この報告書は、Open Checklist Interactive Language（OCIL）のバージョン 2.0 を定義します。OCIL の意図は、質問票と、質問への回答や質問票の最終結果などの関連情報を表現するための標準化された基盤を提供することにより、質問票が、標準化された機械可読な方法で人間とやり取りし、過去のデータ収集で保存された情報を利用できるようにすることです。OCIL 文書は Extensible Markup Language（XML）に基づいています。この報告書は、OCIL 2.0 仕様への適合を主張する IT 製品と OCIL 文書が満たさなければならない要件を定義し、説明します。

1. Introduction

原本 PDF p.7

1. はじめに

The Open Checklist Interactive Language (OCIL) defines a framework for expressing questionnaires that can be used by software to harvest information stored during previous data collection efforts or to collect information from people. OCIL allows organizations to author questionnaires in a standardized format that can be processed by a variety of software products. OCIL also includes constructs for representing such things as questions, instructions that guide users towards an answer, and submission of user-provided documents that provide evidence for responses.

原本 PDF p.7

Open Checklist Interactive Language（OCIL）は、ソフトウェアが過去のデータ収集で保存された情報を取り込んだり、人から情報を収集したりするために使用できる質問票を表現するためのフレームワークを定義します。OCIL により、組織は、さまざまなソフトウェア製品で処理できる標準化された形式で質問票を作成できます。OCIL には、質問、利用者を回答へ導く指示、回答の根拠となる利用者提供の文書の提出といったものを表現するための構成要素も含まれています。

OCIL facilitates uniform data collection and reporting. Other benefits of using OCIL include:

原本 PDF p.7

OCIL は、統一されたデータ収集と報告を容易にします。OCIL を使用するその他の利点には、次のものがあります。

•Performing every manual check in the same manner with all required steps followed, regardless of who performs the check.

原本 PDF p.7

•誰がチェックを実施するかにかかわらず、すべての手動チェックを、必要なすべての手順に従って同じ方法で実施すること。

•Allowing responses to manual checks to be reviewed for auditing purposes.

原本 PDF p.7

•手動チェックへの回答を、監査の目的でレビューできるようにすること。

•Fostering the development of standardized, interoperable capabilities in products for creating, evaluating, and supporting manual checks.

原本 PDF p.7

•手動チェックを作成、評価、支援するための、製品における標準化された相互運用可能な機能の開発を促進すること。

•Fostering collaboration among security-related communities in authoring and composing manual checks.

原本 PDF p.7

•手動チェックの作成と構成における、セキュリティ関連コミュニティ間の協力を促進すること。

•Enhancing the manageability of manual checks.

原本 PDF p.7

•手動チェックの管理性を高めること。

The original motivation for creating OCIL was for development of automated security checklist questionnaires for human interaction. OCIL can be used to help assess security controls related to people and processes when assessment is not feasible or possible with fully automated means. An example is asking users about their participation in security training as part of an automated approach to Federal Information Security Management Act (FISMA) compliance reporting or to support a standardized means for presenting information and evaluating users as part of a security awareness and training program. However, OCIL’s capabilities can be applied to collect human input on any topic. For instance, it can be used for authoring research surveys and academic course exams. OCIL can also be used to harvest information stored during previous data collection efforts and convert it to a standardized format, which can then more easily be aggregated with other data sources and accessed through a single interface, such as a dashboard. Many of the examples presented in this document are security-related, but this is not intended to imply any limitation on OCIL’s applicability.

原本 PDF p.7

OCIL を作成した当初の動機は、人とのやり取りのための自動化されたセキュリティチェックリスト質問票を開発することでした。OCIL は、完全な自動化手段では評価が実現可能でない、または不可能な場合に、人やプロセスに関連するセキュリティ管理策を評価するのに役立ちます。たとえば、Federal Information Security Management Act（FISMA）への準拠報告の自動化された手法の一環として、利用者にセキュリティトレーニングへの参加状況を尋ねる場合や、セキュリティ意識向上およびトレーニングのプログラムの一環として、利用者に情報を提示し評価するための標準化された手段を支援する場合です。ただし、OCIL の機能は、あらゆるトピックについて人からの入力を収集するために適用できます。たとえば、調査研究のアンケートや学術的な授業の試験を作成するために使用できます。OCIL は、過去のデータ収集で保存された情報を取り込んで標準化された形式に変換するためにも使用できます。変換された情報は、他のデータソースとより容易に集約でき、ダッシュボードなどの単一のインターフェースを通じてアクセスできます。この文書で示す例の多くはセキュリティに関連するものですが、これは OCIL の適用範囲に何らかの制限があることを意味するものではありません。

4.1 Relationship to OVAL

原本 PDF p.11

4.1 OVAL との関係

The Open Vulnerability and Assessment Language (OVAL) is used to express standardized, machine-readable rules that can be used to assess the state of a system. In the domain of information security, OVAL is commonly used to determine the presence of vulnerabilities and insecure software configurations through automated means. OVAL reports its findings in a standardized XML-based manner.

原本 PDF p.11

OVAL and OCIL complement each other and they can be considered peers. OVAL is used to collect specified pieces of information from systems directly and automatically, without human interaction; OCIL is used to collect specified pieces of information by harvesting existing sources of collected data or by asking a human to supply it. Both OVAL and OCIL produce XML-based reports, which supports aggregation of OVAL and OCIL results.

原本 PDF p.11

OVAL と OCIL は互いに補完し合うものであり、対等なものと考えることができます。OVAL は、人手を介さずに、システムから指定された情報を直接かつ自動的に収集するために使用されます。OCIL は、収集済みのデータの既存の情報源を取り込むか、人に情報の提供を求めることによって、指定された情報を収集するために使用されます。OVAL と OCIL はどちらも XML ベースの報告書を生成するため、OVAL と OCIL の結果の集約を支援します。

原本 PDF p.31

7.8 Graceful Error Handling

原本 PDF p.33

7.8 適切なエラー処理

When initially processing an OCIL document, an OCIL implementation SHOULD check for all forms of circular references, such as a questionnaire or test action that calls itself, and a question that has a variable that gets its value from the same question. The implementation SHOULD handle these circular references gracefully, such as producing an informative error message detailing the circular references instead of displaying questionnaires containing circular references.

原本 PDF p.33

OCIL 文書を最初に処理する際、OCIL 実装は、questionnaire や test action が自分自身を呼び出す場合や、質問が同じ質問から値を取得する変数を持つ場合など、あらゆる形の循環参照を確認すべきです（SHOULD）。実装は、これらの循環参照を適切に処理すべきです（SHOULD）。たとえば、循環参照を含む questionnaire を表示する代わりに、循環参照の詳細を示す、有益なエラーメッセージを生成します。

An OCIL implementation SHOULD NOT suddenly terminate its execution due to an error condition. OCIL implementations SHOULD handle all exceptional conditions gracefully by performing proper error and exception handling. For all such conditions that do not have handling requirements defined elsewhere in this specification, the implementation SHOULD produce an informative error message. For exceptional conditions involving questionnaire evaluation, implementations MAY set results appropriately, based on the nature of the exceptional condition, and skip a section of a questionnaire or an entire questionnaire to allow evaluation of other questionnaires or questionnaire sections to proceed.

原本 PDF p.33

OCIL 実装は、エラー状態によって実行を突然終了すべきではありません（SHOULD NOT）。OCIL 実装は、適切なエラー処理と例外処理を行うことで、すべての例外的な状況を適切に処理すべきです（SHOULD）。この仕様の他の箇所で処理要件が定義されていないそのようなすべての状況について、実装は有益なエラーメッセージを生成すべきです（SHOULD）。questionnaire の評価に関わる例外的な状況では、実装は、例外的な状況の性質に基づいて結果を適切に設定し、questionnaire の一部または questionnaire 全体をスキップして、他の questionnaire や questionnaire の部分の評価を続行できるようにしてもよいです（MAY）。

Aggregating Results

結果の集約

OCIL can be used to aggregate results from multiple data sources.

An example is using OCIL to convert disparate information into a single standardized format. Supplementing Automated System Checks

原本 PDF p.35

自動化されたシステムチェックの補完

When evaluating a system, OCIL can be used to perform manual checks that cannot be performed in a fully automated manner.

原本 PDF p.35

システムを評価する際、OCIL を使用して、完全に自動化された方法では実施できない手動チェックを実施できます。

An example of this is using OCIL with XCCDF. Suppose that someone writes an XCCDF document containing system security checks to collect evidence to demonstrate PCI-DSS compliance. One of the checks requires a complex evaluation that currently cannot be automated using operating system or application supported application programming interfaces (APIs). Within the document, the author includes a reference to an OCIL document containing a manual check. A security professional assigned to the task of checking the system for compliance loads the XCCDF document into an XCCDF interpreter. Upon reaching a manual check, the XCCDF interpreter loads the OCIL document into the OCIL interpreter (either through a built-in functionality within the XCCDF interpreter or an external OCIL implementation), which asks the security officer a series of questions. The security officer's responses are collected and interpreted. The OCIL results are returned to the XCCDF interpreter, which then continues with the remaining checks and generates OVAL results. The OCIL and OVAL results are aggregated into a single report by the XCCDF interpreter, which can then be used to demonstrate PCI-DSS compliance.

原本 PDF p.35

一例は、OCIL を XCCDF とともに使用することです。PCI-DSS への準拠を実証する証拠を収集するため、システムセキュリティチェックを含む XCCDF 文書を誰かが作成したとします。チェックの 1 つは複雑な評価を必要とし、現時点では、オペレーティングシステムまたはアプリケーションがサポートするアプリケーションプログラミングインターフェース（API）を使用して自動化できません。作成者は、文書内に、手動チェックを含む OCIL 文書への参照を記載します。システムの準拠をチェックする任務を割り当てられたセキュリティ専門家が、XCCDF 文書を XCCDF インタープリターに読み込みます。手動チェックに到達すると、XCCDF インタープリターは、OCIL 文書を OCIL インタープリターに読み込みます（XCCDF インタープリターに組み込まれた機能、または外部の OCIL 実装を通じて）。OCIL インタープリターはセキュリティ担当者に一連の質問をします。セキュリティ担当者の回答が収集され、解釈されます。OCIL の結果は XCCDF インタープリターに返され、XCCDF インタープリターは残りのチェックを続行して OVAL の結果を生成します。OCIL と OVAL の結果は、XCCDF インタープリターによって 1 つの報告書に集約され、PCI-DSS への準拠を実証するために使用できます。

Collecting Information from People

原本 PDF p.35

人からの情報収集

OCIL can be used to collect information from people, such as their knowledge, responsibilities, interests, and opinions.

原本 PDF p.35

OCIL は、人から、その知識、責任、関心、意見などの情報を収集するために使用できます。

An example of this is collecting information from building evacuation coordinators, who are responsible for ensuring that employees and visitors are safely evacuated from the building during emergencies or drills. After each evacuation, all of the coordinators are emailed a request to submit an evacuation report. The email contains a link to a form on the organization’s internal web site; this form is the front-end to an OCIL document. The user answers the questions in the form, such as how long it took to evacuate everyone. In some cases, the answer to a question causes different questions to be asked; for example, responding “yes” to “Were there problems during the evacuation?” would cause additional questions regarding the nature of the problems to be displayed. When the user finishes the form, the results are submitted to a repository, so that the organization’s safety officials can analyze and review all the results.

原本 PDF p.35

一例は、建物の避難調整担当者から情報を収集することです。避難調整担当者は、緊急時や訓練時に、従業員と来訪者が建物から安全に避難することを確実にする責任を負っています。各避難の後、すべての調整担当者に、避難報告書の提出を依頼するメールが送られます。このメールには、組織の社内 Web サイトにあるフォームへのリンクが含まれています。このフォームは、OCIL 文書のフロントエンドです。利用者は、全員が避難するのにかかった時間など、フォームの質問に回答します。場合によっては、質問への回答によって、異なる質問が尋ねられます。たとえば、「避難中に問題がありましたか?」に「はい」と回答すると、問題の性質に関する追加の質問が表示されます。利用者がフォームへの入力を終えると、結果がリポジトリーに提出され、組織の安全担当者がすべての結果を分析し、レビューできるようになります。

Another example of this use case is collecting information during the initial planning of a system audit. Planning may involve identifying systems, networks, applications, and other IT components to be included in the audit. OCIL can be used by auditors to collect information from key personnel about these components. Since this information is collected and stored using standardized, automated means, it can be quickly evaluated by auditors, who select the components to be audited and feed the pertinent information into tools such as vulnerability assessment scanners, thus helping to automate and expedite the assessment process.

原本 PDF p.36

このユースケースの別の例は、システム監査の最初の計画中に情報を収集することです。計画には、監査に含めるシステム、ネットワーク、アプリケーション、その他の IT コンポーネントの特定が含まれる場合があります。監査人は、OCIL を使用して、これらのコンポーネントに関する情報を主要な担当者から収集できます。この情報は、標準化された自動化された手段で収集・保存されるため、監査人が迅速に評価でき、監査人は、監査対象のコンポーネントを選択し、関連する情報を脆弱性評価スキャナーなどのツールに取り込めます。これにより、評価プロセスの自動化と迅速化に役立ちます。

Collecting Text, Files, and Resource References

OCIL can collect blocks of text, copies of files, and references to resources (including URLs) from systems.

原本 PDF p.36

An example is collecting copies of a configuration file from systems. The exact file that needs to be collected from each system depends on certain characteristics of each system’s configuration. This system configuration information was recently collected for a different purpose and is stored in a database. The pertinent information in this database could be harvested through automated techniques and used by an OCIL document to determine which configuration file needs to be collected from each system. 原本 PDF p.36

一例は、システムから構成ファイルのコピーを収集することです。各システムから収集する必要があるファイルは、各システムの構成の特定の特性によって決まります。このシステム構成情報は、最近、別の目的で収集され、データベースに保存されています。このデータベース内の関連情報は、自動化された手法で取り込まれ、各システムからどの構成ファイルを収集する必要があるかを判断するために、OCIL 文書によって使用できます。その後、OCIL 文書は、適切なファイルのコピーを、関連するシステム構成の特性のコピーとともに、後のレビューのために中央サーバーへ転送します。
