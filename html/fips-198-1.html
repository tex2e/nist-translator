Abstract

原本 PDF p.3

要旨

This Standard describes a keyed-hash message authentication code (HMAC), a mechanism for message authentication using cryptographic hash functions. HMAC can be used with any iterative Approved cryptographic hash function, in combination with a shared secret key.

原本 PDF p.3

本標準は、暗号学的ハッシュ関数を用いたメッセージ認証のメカニズムである鍵付きハッシュメッセージ認証コード（HMAC）について記述する。HMACは、共有シークレット鍵と組み合わせることで、反復型の承認済み暗号学的ハッシュ関数であればどれとでも使用できる。

Keywords: computer security, cryptography, HMAC, MAC, message authentication, Federal Information Processing Standards (FIPS).

原本 PDF p.3

キーワード：コンピュータセキュリティ、暗号、HMAC、MAC、メッセージ認証、連邦情報処理標準（FIPS）。

3.Explanation. This Standard specifies an algorithm for applications requiring message authentication. Message authentication is achieved via the construction of a message authentication code (MAC). MACs based on cryptographic hash functions are known as HMACs.

原本 PDF p.4

3.説明。本標準は、メッセージ認証を必要とするアプリケーション向けのアルゴリズムを規定する。メッセージ認証は、メッセージ認証コード（MAC）を構成することによって実現される。暗号学的ハッシュ関数に基づくMACはHMACと呼ばれる。

The purpose of a MAC is to authenticate both the source of a message and its integrity without the use of any additional mechanisms. HMACs have two functionally distinct parameters, a message input and a secret key known only to the message originator and intended receiver(s). Additional applications of keyed-hash functions include their use in challenge-response identification protocols for computing responses, which are a function of both a secret key and a challenge message.

原本 PDF p.4

MACの目的は、追加のメカニズムを用いることなく、メッセージの送信元とその完全性の両方を認証することである。HMACには機能的に異なる2つのパラメータ、すなわちメッセージ入力と、メッセージの作成者および意図された受信者だけが知る秘密鍵がある。鍵付きハッシュ関数の他の用途としては、チャレンジレスポンス型識別プロトコルにおける応答の計算がある。この応答は、秘密鍵とチャレンジメッセージの両方の関数である。

An HMAC function is used by the message sender to produce a value (the MAC) that is formed by condensing the secret key and the message input. The MAC is typically sent to the message receiver along with the message. The receiver computes the MAC on the received message using the same key and HMAC function as were used by the sender, and compares the result computed with the received MAC. If the two values match, the message has been correctly received, and the receiver is assured that the sender is a member of the community of users that share the key.

原本 PDF p.4

HMAC関数は、メッセージの送信者が値（MAC）を生成するために用いる。この値は、秘密鍵とメッセージ入力を圧縮して形成される。MACは通常、メッセージとともにメッセージの受信者に送られる。受信者は、送信者が用いたものと同じ鍵とHMAC関数を用いて受信したメッセージのMACを計算し、計算結果を受信したMACと比較する。2つの値が一致すれば、メッセージは正しく受信されており、受信者は送信者がその鍵を共有する利用者集団の一員であることを確信できる。

1. INTRODUCTION

原本 PDF p.8

1. はじめに

Providing a way to check the integrity of information transmitted over or stored in an unreliable medium is a prime necessity in the world of open computing and communications. Mechanisms that provide such integrity checks based on a secret key are usually called message authentication codes (MACs). Typically, message authentication codes are used between two parties that share a secret key in order to authenticate information transmitted between these parties. This Standard defines a MAC that uses a cryptographic hash function in conjunction with a secret key. This mechanism is called HMAC [HMAC]. HMAC shall use an Approved cryptographic hash function [FIPS 180-3]. HMAC uses the secret key for the calculation and verification of the MACs.

原本 PDF p.8

信頼性の低い媒体を介して送信される情報、またはそうした媒体に保存される情報の完全性を検査する手段を提供することは、オープンなコンピューティングと通信の世界において第一の必要事項である。秘密鍵に基づいてこのような完全性検査を提供するメカニズムは、通常、メッセージ認証コード（MAC）と呼ばれる。メッセージ認証コードは一般に、秘密鍵を共有する二者の間で、両者間で送信される情報を認証するために用いられる。本標準は、暗号学的ハッシュ関数を秘密鍵と組み合わせて用いるMACを定義する。このメカニズムをHMAC [HMAC] と呼ぶ。HMACは承認済みの暗号学的ハッシュ関数 [FIPS 180-3] を使用しなければならない。HMACは、MACの計算および検証に秘密鍵を用いる。

3. CRYPTOGRAPHIC KEYS

原本 PDF p.10

3. 暗号鍵

HMAC uses a key, K, of appropriate security strength, as discussed in NIST Special Publication (SP) 800-107 [SP 800-107], Recommendation for Applications Using Approved Hash Algorithms. When an application uses a K longer than B-bytes, then it shall first hash the K using H and then use the resultant L-byte string as the key \(K_0\); detail can be found in Table 1 in Section 4 below.

原本 PDF p.10

HMAC は、NIST Special Publication (SP) 800-107 [SP 800-107]、Recommendation for Applications Using Approved Hash Algorithms で論じられているとおり、適切なセキュリティ強度を持つ鍵 K を使用する。アプリケーションが B バイトより長い K を使用する場合、まず H を用いて K をハッシュし、得られた L バイトの文字列を鍵 \(K_0\) として使用しなければならない。詳細は後述の第 4 節の表 1 を参照のこと。

4. HMAC SPECIFICATION

原本 PDF p.10

4. HMAC の仕様

To compute a MAC over the data ‘text’ using the HMAC function, the following operation is performed:

原本 PDF p.10

HMAC 関数を用いてデータ ‘text’ に対する MAC を計算するには、次の演算を行う。

\(MAC(text) = HMAC(K, text) = H((K_0 \oplus opad) \| H((K_0 \oplus ipad) \| text))\)

原本 PDF p.10

\(MAC(text) = HMAC(K, text) = H((K_0 \oplus opad) \| H((K_0 \oplus ipad) \| text))\)

Table 1 illustrates the step by step process in the HMAC algorithm, which is depicted in Figure 1.

Table 1: The HMAC Algorithm

原本 PDF p.10

表 1：HMAC アルゴリズム

STEPSSTEP-BY-STEP DESCRIPTION
Step 1If the length of \(K = B\): set \(K_0 = K\). Go to step 4.
Step 2If the length of \(K > B\): hash \(K\) to obtain an \(L\) byte string, then append \((B-L)\) zeros to create a B-byte string \(K_0\) (i.e., \(K_0 = \mathrm{H}(K) \| 00...00\)). Go to step 4.
Step 3If the length of \(K < B\): append zeros to the end of \(K\) to create a \(B\)-byte string \(K_0\) (e.g., if \(K\) is 20 bytes in length and \(B = 64\), then \(K\) will be appended with 44 zero bytes x’00’).
Step 4Exclusive-Or \(K_0\) with \(ipad\) to produce a \(B\)-byte string: \(K_0 \oplus ipad\).
Step 5Append the stream of data 'text' to the string resulting from step 4: \((K_0 \oplus ipad) \| text\).
Step 6Apply \(H\) to the stream generated in step 5: \(\mathrm{H}((K_0 \oplus ipad) \| text)\).
Step 7Exclusive-Or \(K_0\) with \(opad\): \(K_0 \oplus opad\).
Step 8Append the result from step 6 to step 7: \((K_0 \oplus opad) \| \mathrm{H}((K_0 \oplus ipad) \| text)\).
Step 9Apply \(H\) to the result from step 8: \(H((K_0 \oplus opad) \| H((K_0 \oplus ipad) \| text))\).

手順1長さが \(K = B\) の場合：\(K_0 = K\) とする。手順4に進む。

手順3長さが \(K < B\) の場合：\(K\) の末尾にゼロを付加して \(B\) バイトの文字列 \(K_0\) を作成する（例えば、\(K\) の長さが20バイトで \(B = 64\) の場合、\(K\) には44個のゼロバイト x’00’ が付加される）。
手順4\(K_0\) と \(ipad\) の排他的論理和をとり、\(B\) バイトの文字列 \(K_0 \oplus ipad\) を生成する。
手順5手順4の結果の文字列にデータストリーム 'text' を付加する：\((K_0 \oplus ipad) \| text\)。
手順6手順5で生成したストリームに \(H\) を適用する：\(\mathrm{H}((K_0 \oplus ipad) \| text)\)。

5. TRUNCATION

原本 PDF p.11

5. 切り詰め

A well-known practice with MACs is to truncate their outputs (i.e., the length of the MACs used is less than the length of the output of the HMAC function L). Applications of this standard may truncate the outputs of the HMAC. When truncation is used, the λ leftmost bits of the output of the HMAC function shall be used as the MAC. For information about the choice of λ and the security implications of using truncated outputs of the HMAC function, see SP 800-107.

原本 PDF p.11

MAC の出力を切り詰める（すなわち、使用する MAC の長さを HMAC 関数の出力長 L より短くする）ことは、よく知られた慣行である。本標準のアプリケーションは、HMAC の出力を切り詰めてもよい。切り詰めを行う場合、HMAC 関数の出力の左端 λ ビットを MAC として使用しなければならない。λ の選び方と、HMAC 関数の切り詰めた出力を使用することのセキュリティ上の影響については、SP 800-107 を参照のこと。

6. IMPLEMENTATION NOTE

原本 PDF p.11

6. 実装上の注記

The HMAC algorithm is specified for an arbitrary Approved iterative cryptographic hash function, H. In the HMAC algorithm, values of the ipad and the opad depend on the block size, B, of the Approved hash function. An HMAC implementation can easily replace one Approved iterative hash function, H, with another Approved iterative hash function, H’ by generating new ipad and opad using the block size of H’ instead of H as defined in Section 2.3.

原本 PDF p.11

HMAC アルゴリズムは、任意の承認された反復型暗号ハッシュ関数 H について規定されている。HMAC アルゴリズムでは、ipad と opad の値は承認されたハッシュ関数のブロックサイズ B に依存する。HMAC の実装では、第 2.3 節の定義に従い H ではなく H’ のブロックサイズを用いて新たな ipad と opad を生成することで、ある承認された反復型ハッシュ関数 H を別の承認された反復型ハッシュ関数 H’ に容易に置き換えることができる。

Conceptually, the intermediate results of the compression function on the B-byte blocks \((K_0 \oplus ipad)\) and \((K_0 \oplus opad)\) can be precomputed once, at the time of generation of the key K, or before its first use. These intermediate results can be stored and then used to initialize H each time that a message needs to be authenticated using the same key. For each authenticated message using the key K, this method saves the application of the hash function of H on two B-byte blocks (i.e., on \((K \oplus ipad)\) and \((K \oplus opad)\)). This saving may be significant when authenticating short streams of data. These stored intermediate values shall be treated and protected in the same manner as secret keys.

原本 PDF p.12

概念的には、B バイトのブロック \((K_0 \oplus ipad)\) と \((K_0 \oplus opad)\) に対する圧縮関数の中間結果は、鍵 K の生成時または鍵の初回使用前に一度だけ事前計算しておくことができる。これらの中間結果を保存しておき、同じ鍵を用いてメッセージを認証する必要が生じるたびに H の初期化に使用できる。この方法により、鍵 K を用いて認証するメッセージごとに、二つの B バイトのブロック（すなわち \((K \oplus ipad)\) と \((K \oplus opad)\)）に対するハッシュ関数 H の適用が省かれる。短いデータストリームを認証する場合、この節約は大きくなりうる。保存したこれらの中間値は、秘密鍵と同じ方法で取り扱い、保護しなければならない。

Choosing to implement HMAC in this manner has no effect on interoperability.

原本 PDF p.12

HMAC をこの方法で実装することを選択しても、相互運用性には影響しない。

Object identifiers (OIDs) for HMAC are posted at http://csrc.nist.gov/groups/ST/crypto_apps_infra/csor/algorithms.html, along with procedures for adding new OIDs.

原本 PDF p.12

HMAC のオブジェクト識別子（OID）は、新たな OID を追加する手順とともに http://csrc.nist.gov/groups/ST/crypto_apps_infra/csor/algorithms.html に掲載されている。

Examples of HMAC are available at http://csrc.nist.gov/groups/ST/toolkit/examples.html.

原本 PDF p.12

HMAC の例は http://csrc.nist.gov/groups/ST/toolkit/examples.html で入手できる。
