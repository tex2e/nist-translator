Abstract

原本 PDF p.2

概要

One of the criteria used to evaluate the Advanced Encryption Standard candidate algorithms was their demonstrated suitability as random number generators. That is, the evaluation of their output utilizing statistical tests should not provide any means by which to computationally distinguish them from a truly random source. This internal report lists several characteristics which an encryption algorithm exhibiting random behavior should possess, describes how the output for each candidate algorithm was evaluated for randomness, discusses what has been learned utilizing the NIST statistical tests, and finally provides an interpretation of the results.

1. Introduction

1. はじめに

One of the criteria used to evaluate the Advanced Encryption Standard (AES) candidate algorithms was their demonstrated suitability as random number generators. That is, the evaluation of their outputs utilizing statistical tests should not provide any means by which to computationally distinguish them from truly random sources. The evaluation reported on here focused on 128-bit keys. Future work will address the 192-bit and 256-bit key sizes.

次世代暗号標準（AES）の候補アルゴリズムを評価するために用いられた基準の 1 つは、乱数生成器としての適性が実証されていることでした。すなわち、統計的検定を用いて出力を評価したときに、それらを真にランダムな発生源から計算量的に区別できる手段が得られてはなりません。ここで報告する評価は、128 ビット鍵に焦点を当てました。今後の作業では、192 ビットと 256 ビットの鍵長を扱います。

This paper lists several characteristics that an encryption algorithm exhibiting random behavior should possess, describes how the output for each candidate algorithm was evaluated for randomness, discusses what has been learned utilizing the NIST statistical tests, and finally provides an interpretation of the results.

2.1 128-Bit Key Avalanche and Plaintext Avalanche

原本 PDF p.3

2.1 128 ビット鍵の Key Avalanche と Plaintext Avalanche

To examine the sensitivity of individual algorithms to changes in input parameters (i.e., the key or the plaintext), 384 binary sequences were analyzed in each case. In the key avalanche case, 384 sequences (1,048,576 bits per sequence) were parsed from the resulting string, constructed as follows: given 24,576 random 128-bit keys, and a plaintext of all zeroes, 3,145,728 derived blocks were concatenated. Each derived block is based on the XOR of the “ciphertext formed using the fixed plaintext and a random 128-bit key,” and the “ciphertext formed using the fixed plaintext and the perturbed random 128-bit key with the ith bit changed, for \(1 \le i \le 128\).” In the case of the plaintext avalanche property, substitute “random plaintext(s)“ for “random 128-bit key(s)” in the above description, “128-bit key of all-zeroes” for “plaintext of all zeroes” and “fixed 128-bit key” for “fixed plaintext.”

原本 PDF p.3

入力パラメーター（すなわち、鍵または平文）の変化に対する個々のアルゴリズムの感度を調べるため、それぞれのケースで 384 個の 2 値系列を分析しました。Key Avalanche の場合、384 個の系列（1 系列あたり 1,048,576 ビット）は、次のように構成した文字列から切り出しました。24,576 個のランダムな 128 ビット鍵と、すべてゼロの平文が与えられたとき、3,145,728 個の派生ブロックを連結しました。各派生ブロックは、「固定の平文とランダムな 128 ビット鍵を用いて形成した暗号文」と、「固定の平文と、摂動を加えたランダムな 128 ビット鍵を用いて形成した暗号文（\(1 \le i \le 128\) に対して i 番目（ith）のビットを変更）」との XOR に基づいています。Plaintext Avalanche 特性の場合は、上記の説明の「ランダムな 128 ビット鍵」を「ランダムな平文」に、「すべてゼロの平文」を「すべてゼロの 128 ビット鍵」に、「固定の平文」を「固定の 128 ビット鍵」に置き換えます。

2.2 Plaintext/Ciphertext Correlation

原本 PDF p.3

2.2 Plaintext/Ciphertext Correlation

In order to study the correlation of plaintext/ciphertext pairs, 128 sequences (1,048,576 bits per sequence) were examined for each algorithm. Given a random 128-bit key and 8,128 random plaintext blocks, a binary sequence was constructed concatenating 8,128 derived blocks (where a derived block is the result of applying the XOR operator on the plaintext block and its corresponding ciphertext block computed in the ECB mode).

原本 PDF p.3

平文と暗号文のペアの相関を調べるため、各アルゴリズムについて 128 個の系列（1 系列あたり 1,048,576 ビット）を検査しました。ランダムな 128 ビット鍵と 8,128 個のランダムな平文ブロックが与えられたとき、8,128 個の派生ブロック（派生ブロックとは、平文ブロックと、ECB モードで計算したそれに対応する暗号文ブロックに XOR 演算子を適用した結果）を連結して、2 値系列を構成しました。

Using the 8,128 (previously selected) plaintext blocks, the procedure was repeated 127 times, i.e., once for each (additional) random 128-bit key.

原本 PDF p.4

8,128 個の（先に選んだ）平文ブロックを使って、この手順を 127 回、すなわち（追加の）ランダムな 128 ビット鍵ごとに 1 回ずつ繰り返しました。

2.3 Cipher Block Chaining Mode

原本 PDF p.4

2.3 Cipher Block Chaining Mode

Given a random 128-bit key, a 128-bit initialization vector (IV) of all zeroes, and a 128-bit plaintext block (PT) of all zeroes, a binary sequence of 1,048,576 bits was constructed using ciphertext computed in the CBC mode. That is, a binary sequence consisted of 8,192 concatenated 128-bit ciphertext blocks. The first ciphertext block (\(\mathrm{CT}_1\)) is defined by \(\mathrm{CT}_1 = E_k(\mathrm{IV} \oplus \mathrm{PT})\). Subsequent ciphertext blocks were defined by \(\mathrm{CT}_{i+1} = E_k(\mathrm{CT}_i \oplus \mathrm{PT})\) for \(1 \le i \le 8{,}191\). In all, 300 binary sequences were constructed, each with a different random 128-bit key.

原本 PDF p.4

ランダムな 128 ビット鍵、すべてゼロの 128 ビットの初期化ベクトル（IV）、およびすべてゼロの 128 ビット平文ブロック（PT）が与えられたとき、CBC モードで計算した暗号文を用いて、1,048,576 ビットの 2 値系列を構成しました。すなわち、2 値系列は、連結した 8,192 個の 128 ビット暗号文ブロックで構成されます。最初の暗号文ブロック（\(\mathrm{CT}_1\)）は、\(\mathrm{CT}_1 = E_k(\mathrm{IV} \oplus \mathrm{PT})\) で定義されます。それ以降の暗号文ブロックは、\(\mathrm{CT}_{i+1} = E_k(\mathrm{CT}_i \oplus \mathrm{PT})\)（\(1 \le i \le 8{,}191\)）で定義されました。全体で 300 個の 2 値系列を構成し、それぞれに異なるランダムな 128 ビット鍵を使いました。

2.4 Random Plaintext/Random 128-Bit Keys

In order to examine the randomness of ciphertext (based on random plaintext and random 128-bit keys), 128 sequences were constructed. Each sequence was a result of the concatenation of 8,128 ciphertext blocks using 8,128 random plaintexts and a random 128-bit key in the ECB mode.

原本 PDF p.4

（ランダムな平文とランダムな 128 ビット鍵に基づく）暗号文のランダムネスを調べるため、128 個の系列を構成しました。各系列は、ECB モードで 8,128 個のランダムな平文とランダムな 128 ビット鍵を使って得た、8,128 個の暗号文ブロックを連結した結果です。

2.5 Low Density Plaintext and Low Density 128-Bit Keys

原本 PDF p.4

2.5 Low Density Plaintext と Low Density 128-Bit Keys

Two data sets were created based on low-density blocks used as either plaintext or 128-bit keys. Each data set consisted of 128 sequences. Each sequence consisted of 8,257 ciphertext blocks computed in the ECB mode. These ciphertext blocks were formed from one all zero plaintext block (128-bit key), 128 plaintext blocks (128-bit keys) of a single one and 127 zeroes (the one appearing in each of the possible 128 bit positions), and 8,128 plaintext blocks (128-bit keys) of two ones and 126 zeroes (the two ones appearing in each combination of two bit positions within the 128-bit positions).

原本 PDF p.4

平文または 128 ビット鍵のいずれかとして使う低密度ブロックに基づいて、2 つのデータセットを作成しました。各データセットは 128 個の系列で構成されました。各系列は、ECB モードで計算した 8,257 個の暗号文ブロックで構成されました。これらの暗号文ブロックは、すべてゼロの平文ブロック（128 ビット鍵）1 個、1 が 1 つと 0 が 127 個からなる平文ブロック（128 ビット鍵）128 個（この 1 は、取り得る 128 のビット位置のそれぞれに現れます）、および 1 が 2 つと 0 が 126 個からなる平文ブロック（128 ビット鍵）8,128 個（この 2 つの 1 は、128 のビット位置のうち 2 つのビット位置のあらゆる組み合わせに現れます）から形成しました。

2.6 High Density Plaintext と High Density 128-Bit Keys

3. Empirical Analysis

原本 PDF p.4

3. 経験的分析

Table 2 describes the breakdown of the simulation-input parameters per data category. The number of sequences utilized in the samples varied from 128 to 384. Based on earlier experiments conducted on pseudo-random number generators with sequences consisting of 1,000,000 bits, sequences consisting of \(2^{20}\) (i.e., 1,048,576) bits were chosen. In four instances, sequences consisting of 1,056,896 bits were chosen, which corresponded to the number of bits in 8,257 ciphertexts. The number of statistical tests applied varied from 59 to 187. The difference was due to the specification of alternative input parameters such as the number of templates to be used.

原本 PDF p.4

表 2 は、データ種別ごとのシミュレーション入力パラメーターの内訳を示しています。標本に用いた系列の数は 128 から 384 までさまざまでした。1,000,000 ビットからなる系列を用いた擬似乱数生成器に対する以前の実験に基づき、\(2^{20}\)（すなわち 1,048,576）ビットからなる系列を選びました。4 つのケースでは、8,257 個の暗号文のビット数に相当する、1,056,896 ビットからなる系列を選びました。適用した統計的検定の数は 59 から 187 までさまざまでした。この違いは、使用するテンプレートの数などの、代替の入力パラメーターの指定によるものでした。

For each experiment, the significance level was fixed at 0.01, which implies that, ideally, no more than one binary sequence should be rejected for each sample of 100 binary sequences evaluated by a statistical test. However, in all likelihood, any given data set will deviate from this ideal case. A more realistic interpretation is to use a confidence interval (CI) for the “proportion of binary sequences” that should pass at the 0.01 level. Thus, a data set that fails more than 5% of the sequences is flagged as suspect.

原本 PDF p.5

各実験で、有意水準は 0.01 に固定しました。これは、理想的には、統計的検定で評価する 2 値系列 100 個の標本ごとに、棄却される 2 値系列は 1 個以下となることを意味します。しかし、実際には、どのデータセットもこの理想的なケースから逸脱する可能性が高いです。より現実的には、有意水準 0.01 で合格するはずの「2 値系列の割合」に対して信頼区間（CI）を用いて解釈します。したがって、系列の 5% を超えて不合格となるデータセットは、疑わしいものとして印を付けます。

4. Conclusion

原本 PDF p.7

4. 結論

During round one testing, numerous statistical tests were applied on 135 sets of data, which collectively span many well-known properties that any good cryptographic algorithm should satisfy. These properties include any detectable correlation between plaintext/ciphertext pairs, any detectable bias due to single bit changes to either a plaintext or a 128-bit key, in addition to many others.

原本 PDF p.7

第 1 ラウンドの検定では、135 組のデータに多数の統計的検定を適用しました。これらは全体として、優れた暗号アルゴリズムが満たすべき多くのよく知られた性質を網羅しています。これらの性質には、平文と暗号文のペアの間に検出可能な相関がないこと、平文または 128 ビット鍵の 1 ビットの変化に起因する検出可能な偏りがないことなどが含まれ、そのほかにも多くあります。

It appears that the HPC algorithm is non-random given the statistically significant results obtained at the 0.01 level for the 128-bit key avalanche data set. Unfortunately, the results for five algorithms, Crypton3, DEAL4, Frog5, RC66 and Twofish7 are inconclusive. Although preliminary testing suggests minor deviations from randomness8 for these five algorithms, one sample alone cannot provide sufficient evidence. In each case more samples should be evaluated to determine whether statistically significant results are consistently present.

原本 PDF p.7

HPC アルゴリズムは、128 ビット鍵の Key Avalanche データセットで 0.01 の水準で統計的に有意な結果が得られたことから、ランダムでないように見えます。残念ながら、5 つのアルゴリズム、Crypton3、DEAL4、Frog5、RC66、Twofish7 の結果は、結論に至りません。予備的な検定は、これら 5 つのアルゴリズムにランダムネスからのわずかな逸脱8があることを示唆していますが、標本が 1 つだけでは十分な証拠にはなりません。いずれの場合も、統計的に有意な結果が一貫して存在するかどうかを判定するために、より多くの標本を評価すべきです。

It is worth noting that the specific statistical tests that predominantly flagged several algorithms as suspect were the cumulative sums (cusum) test and the random excursion test. To further evaluate the cusum test, extensive simulations were conducted on the SHA-1 generator and the Twofish algorithm. The results suggest that data flagged as non-random for the Twofish and RC6 algorithms should be treated as statistical anomalies. Similarly, due to the natural filtering process for the random excursion test, small sample sizes may incorrectly lead one to commit a type I error, i.e., labeling data as nonrandom when it truly appears to be random.

原本 PDF p.8

いくつかのアルゴリズムを疑わしいものとして主に指摘した具体的な統計的検定は、累積和（cusum）検定とランダムエクスカーション検定であったことは注目に値します。cusum 検定をさらに評価するため、SHA-1 生成器と Twofish アルゴリズムに対して大規模なシミュレーションを実施しました。その結果は、Twofish と RC6 のアルゴリズムでランダムでないと指摘されたデータは、統計的な異常として扱うべきであることを示唆しています。同様に、ランダムエクスカーション検定の自然なフィルタリング過程のため、標本サイズが小さいと、第一種の過誤、すなわち、データが真にランダムに見えるときにランダムでないとラベル付けする誤りを犯す場合があります。

For all of the remaining algorithms: CAST-256, DFC, E2, LOKI97, MAGENTA, MARS, RIJNDAEL, SAFER+, and SERPENT, the results to date suggest that there is no deviation from randomness.

原本 PDF p.8

残りのすべてのアルゴリズム、すなわち CAST-256、DFC、E2、LOKI97、MAGENTA、MARS、RIJNDAEL、SAFER+、SERPENT については、これまでの結果は、ランダムネスからの逸脱がないことを示唆しています。

Appendix: Description of the Statistical Tests

原本 PDF p.9

付録: 統計的検定の説明

Frequency Test: The purpose of this test is to determine whether the number of ones and zeros in a sequence are approximately the same as would be expected for a truly random sequence.

原本 PDF p.9

Frequency Test: この検定の目的は、系列中の 1 と 0 の数が、真にランダムな系列で期待される数とほぼ同じかどうかを判定することです。

Block Frequency Test: The purpose of this test is to determine whether the frequency of m-bit blocks in a sequence appears as often as would be expected for a truly random sequence.

原本 PDF p.9

Block Frequency Test: この検定の目的は、系列中の m ビットブロックの頻度が、真にランダムな系列で期待されるのと同じ頻度で現れるかどうかを判定することです。

Cumulative Sums Forward (Reverse) Test: The purpose of this test is to determine whether the maximum of the cumulative sums in a sequence is too large or too small; indicative of too many ones or zeroes in the early (late) stages.

原本 PDF p.9

Cumulative Sums Forward (Reverse) Test: この検定の目的は、系列中の累積和の最大値が大きすぎるか小さすぎるかを判定することです。これは、前（後）の段階で 1 または 0 が多すぎることを示します。

Runs Test: The purpose of this test is to determine whether the number of runs of ones and zeros of various lengths is as expected for a random sequence. In particular, this test determines whether the oscillation between such substrings is too fast or too slow.

原本 PDF p.9

Runs Test: この検定の目的は、さまざまな長さの 1 と 0 のランの数が、ランダムな系列で期待されるとおりかどうかを判定することです。特にこの検定は、そのような部分文字列の間の振動が速すぎるか遅すぎるかを判定します。

Long Runs of Ones Test: The purpose of this test is to determine whether the distribution of long runs of ones agrees with the theoretical probabilities.

原本 PDF p.9

Long Runs of Ones Test: この検定の目的は、1 の長いランの分布が理論的な確率と一致するかどうかを判定することです。

Rank Test: The purpose of this test is to determine whether the distribution of the rank of 32x32 bit matrices agrees with the theoretical probabilities.

原本 PDF p.9

Rank Test: この検定の目的は、32x32 ビット行列のランクの分布が理論的な確率と一致するかどうかを判定することです。

Spectral (Discrete Fourier Transform) Test: The purpose of this test is to determine whether the spectral frequency of the binary sequence agrees with what would be expected for a truly random sequence.

原本 PDF p.9

Spectral (Discrete Fourier Transform) Test: この検定の目的は、2 値系列のスペクトル周波数が、真にランダムな系列で期待されるものと一致するかどうかを判定することです。

Non-periodic Templates Test: The purpose of this test is to determine whether the number of occurrences for a specified nonperiodic template agrees with the number expected for a truly random sequence.

原本 PDF p.9

Non-periodic Templates Test: この検定の目的は、指定した非周期テンプレートの出現数が、真にランダムな系列で期待される数と一致するかどうかを判定することです。

Overlapping Template Test: The purpose of this test is to determine whether the number of occurrences for a template of all ones agrees with what is expected for a truly random sequence.

原本 PDF p.9

Overlapping Template Test: この検定の目的は、すべて 1 のテンプレートの出現数が、真にランダムな系列で期待される数と一致するかどうかを判定することです。

Universal Statistical Test: The purpose of this test is to determine whether a binary sequence does not compress beyond what is expected of a truly random sequence.

原本 PDF p.9

Universal Statistical Test: この検定の目的は、2 値系列が、真にランダムな系列で期待される程度を超えて圧縮できないかどうかを判定することです。

Approximate Entropy Test: The purpose of this test is to compare the frequency of overlapping blocks of two consecutive/adjacent lengths (m and m+1) against the expected result for a normally distributed sequence. In short, it determines whether a sequence appears more regular than is expected from a truly random sequence.

原本 PDF p.9

Approximate Entropy Test: この検定の目的は、連続する（隣り合う）2 つの長さ（m と m+1）の重なるブロックの頻度を、正規分布に従う系列に対して期待される結果と比較することです。要するに、系列が、真にランダムな系列から期待されるよりも規則的に見えるかどうかを判定します。

Random Excursion Test: The purpose of this test is to examine the number of cycles within a sequence and determine whether the number of visits to a given state, [-4, -1] and [1, 4], exceeds the expected for a truly random sequence.

原本 PDF p.10

Random Excursion Test: この検定の目的は、系列内のサイクル数を調べ、与えられた状態 [-4, -1] と [1, 4] への訪問回数が、真にランダムな系列で期待される回数を超えているかどうかを判定することです。

Random Excursion Variant Test: The purpose of this test is to determine if the total number of visits to states, between [-9, -1] and [1, 9] exceeds the expected for a truly random sequence.

原本 PDF p.10

Random Excursion Variant Test: この検定の目的は、[-9, -1] と [1, 9] の間の状態への訪問の総数が、真にランダムな系列で期待される数を超えているかどうかを判定することです。

Lempel-Ziv Complexity Test: The purpose of this test is to determine whether or not the sequence compresses no more than a truly random sequence.

原本 PDF p.10

Lempel-Ziv Complexity Test: この検定の目的は、系列が、真にランダムな系列以上には圧縮されないかどうかを判定することです。

Linear Complexity Test: The purpose of this test is to determine whether or not the sequence is complex enough to be considered truly random.

原本 PDF p.10

Linear Complexity Test: この検定の目的は、系列が、真にランダムと見なせるほど複雑かどうかを判定することです。
