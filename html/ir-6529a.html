[要約] NIST IR 6529A は、Common Biometric Exchange Formats Framework（CBEFF）の仕様を示した報告書であり、2001 年 1 月に NISTIR 6529 として発行された当初の CBEFF を拡張し改訂した版です。この仕様は、複数の生体認証技術を支援し、生体データの交換を可能にすることで、生体認証に基づくアプリケーションやシステムの相互運用性を促進するために必要な、共通のデータ要素群を規定します。当初の仕様からの変更点として、CBEFF Nested Structure、Subheader/Basic Structure Count、Patron Format B などの新しい機能やフィールドが追加されています。CBEFF は、生体データレコードに含まれる実際の生体データの内容や形式を規定せず、生体データの不適切な流布や使用からの個人のプライバシーの保護も適用範囲に含まれません。

Foreword

原本 PDF p.5

まえがき

This specification, the Common Biometric Exchange Formats Framework, is an augmented and revised version of the original CBEFF, the Common Biometric Exchange File Format, published in January 2001 as NISTIR 6529. This version, NISTIR 6529-A, was developed by the CBEFF team based on the specification approved by the Biometrics Interoperability, Performance, and Assurance Working Group (NIST/BC WG) co-sponsored by NIST and the Biometric Consortium.

原本 PDF p.5

本仕様である Common Biometric Exchange Formats Framework は、2001 年 1 月に NISTIR 6529 として発行された、当初の CBEFF（Common Biometric Exchange File Format）を拡張し改訂した版です。この NISTIR 6529-A は、NIST と Biometric Consortium が共同で後援する Biometrics Interoperability, Performance, and Assurance Working Group（NIST/BC WG）が承認した仕様に基づいて、CBEFF チームが策定しました。

Summary of Changes from the original CBEFF specification (NISTIR 6529)

原本 PDF p.5

当初の CBEFF 仕様（NISTIR 6529）からの変更点の概要

In addition to the name change, which reflects more accurately the scope of the specification, this revised version incorporates the following new features:

原本 PDF p.5

本仕様の範囲をより正確に反映するための名称変更に加えて、この改訂版は次の新しい機能を取り入れています。

•A CBEFF Nested Structure. This structure consists of a Root Header followed by optional Sub-Headers, one or more CBEFF Basic Structures, and an optional Signature Block. A CBEFF nested structure can include: (a) standard or non-standard biometric data; (b) challenge data; and (c) payload. A nested structure has been specified in order to support multiple biometric data types (e.g., finger, face and voice) and/or multiple biometric data blocks of the same biometric type (e.g., finger biometric data blocks from more than one finger) within a CBEFF data structure. Nesting CBEFF structures accommodate such requirements and avoids having to utilize multiple consecutive CBEFF records for one specific operation.

原本 PDF p.5

•CBEFF Nested Structure。この構造は、Root Header に続く、任意の Sub-Header、1 つ以上の CBEFF Basic Structure、および任意の Signature Block で構成されます。CBEFF Nested Structure には、（a）標準または非標準の生体データ、（b）チャレンジデータ、（c）ペイロードを含めることができます。Nested Structure は、複数の種類の生体データ（たとえば、指、顔、声）や、同じ種類の生体データの複数のブロック（たとえば、複数の指に由来する指の生体データブロック）を、1 つの CBEFF データ構造の中に含められるように規定されました。CBEFF 構造を入れ子にすることで、そのような要件に対応でき、1 つの特定の操作のために複数の CBEFF レコードを連続して使う必要がなくなります。

•A Subheader/Basic Structure Count. The CBEFF nested structure has required defining this new field. This optional field specifies the number of nested levels below the current level in a CBEFF nested structure. This field has a value of zero in the lowest level of a nested structure.

原本 PDF p.5

•Subheader/Basic Structure Count。CBEFF Nested Structure では、この新しいフィールドを定義する必要がありました。この任意のフィールドは、CBEFF Nested Structure において、現在の階層より下にある入れ子の階層の数を指定します。このフィールドの値は、Nested Structure の最下位の階層ではゼロです。

•The following additional and redefined fields:

原本 PDF p.5

•次のフィールドが追加または再定義されました。

•A Patron Format Identifier optional field that is used in nested structures to identify the CBEFF Patron Format of the next lower level in the structure.

原本 PDF p.5

•Patron Format Identifier。入れ子構造で、構造内の 1 つ下の階層の CBEFF Patron Format を識別するために使われる、任意のフィールドです。

•A Biometric Feature optional field to further define the type of biometric data being placed in a CBEFF record.

原本 PDF p.5

•Biometric Feature。CBEFF レコードに格納される生体データの種類をさらに定義するための、任意のフィールドです。

•A Validity Period optional field to denote the period (not before-not after) when the biometric data block is valid..

原本 PDF p.5

•Validity Period。生体データブロックが有効である期間（開始日と終了日）を示すための、任意のフィールドです。

•A modified definition of the Creator field. In this specification the Creator (optional field) specifies the organizational entity (e.g., issuer or application) responsible for the generation of the biometric data.

原本 PDF p.5

•Creator フィールドの定義の変更。本仕様では、Creator（任意のフィールド）は、生体データの生成に責任を持つ組織上の主体（たとえば、発行者やアプリケーション）を指定します。

•Addition of a Product Identifier (PID) field. This field identifies the entity (e.g., Biometric Service Provider (BSP) or transformation application) that created the biometric data object. This entity may or may not be the same as the entity which defined the format of the created data within the biometric data block.

原本 PDF p.5

•Product Identifier（PID）フィールドの追加。このフィールドは、生体データオブジェクトを作成した主体（たとえば、Biometric Service Provider（BSP）や変換アプリケーション）を識別します。この主体は、生体データブロック内の作成されたデータの形式を定義した主体と同じ場合も、異なる場合もあります。

•An Index field. This optional field contains a unique value associated with a specific instance of biometric reference (enrollment) data. It may represent a database index. Uniqueness pertains only to a specific database. Use and management of this data is the responsibility of the application.

原本 PDF p.5

•Index フィールド。この任意のフィールドは、生体の参照（登録）データの特定のインスタンスに関連付けられた一意の値を含みます。データベースのインデックスを表す場合があります。一意性は特定のデータベースにのみ関係します。このデータの使用と管理は、アプリケーションの責任です。

•A Challenge-Response field. This optional field specifies the type of information used to present a challenge to the user or the system.

原本 PDF p.5

•Challenge-Response フィールド。この任意のフィールドは、ユーザーまたはシステムにチャレンジを提示するために使われる情報の種類を指定します。

•A Payload field: This optional field shall contain data (e.g. a person-identification-number) to be attached in a secure way to biometric reference data and used by a service system (e.g. access control system) in case the biometric verification is positive. Reference data is to be specified by the CBEFF Patron. Examples include a filename, database item, or URL.

Background

原本 PDF p.6

背景

On February 21st 1999, the Information Technology Laboratory of the National Institute of Standards and Technology (NIST) and the Biometric Consortium sponsored a Workshop to discuss the potential for reaching industry consensus on a common fingerprint template format. The participants identified the need for a “technology-blind” biometric format that would facilitate the handling of different biometric types, versions, and biometric data structures in a common way. This common format would facilitate exchange and interoperability of biometric data. (A “technology-blind biometric format would include all modalities of biometrics and would not bias, encourage, or discourage any particular vendor or biometric technology from another. It would not attempt to translate among different biometric technologies, but would identify them and facilitate their co-existence”) The content of the biometric data structures (e.g., raw or processed biometric data) would not be defined in the common framework format.

原本 PDF p.6

1999 年 2 月 21 日に、米国国立標準技術研究所（NIST）の情報技術研究所と Biometric Consortium は、共通の指紋テンプレート形式について業界の合意に至る可能性を議論するワークショップを後援しました。参加者は、異なる生体認証の種類、バージョン、生体データ構造を共通の方法で扱いやすくする、「技術に中立」な生体情報フォーマットの必要性を指摘しました。この共通フォーマットは、生体データの交換と相互運用性を促進します。（「技術に中立な生体情報フォーマット」は、すべての生体認証モダリティを含み、特定のベンダーまたは生体認証技術を他より優遇したり、奨励したり、抑制したりしません。異なる生体認証技術間の変換を試みるのではなく、それらを識別し、共存を促進します。）生体データ構造の内容（たとえば、生の生体データまたは処理済みの生体データ）は、共通のフレームワークフォーマットでは定義されません。

The CBEFF’s initial conceptual definition was achieved through a series of three Workshops co-sponsored by the National Institute of Standards and Technology and the Biometric Consortium on May 10, September 17, and December 1, 1999. A Technical Development Team, formed as a result of these Workshops, developed the original version of CBEFF (NISTIR 6529) To ensure that the biometric data structure would be in agreement with other biometric standards efforts, the development was coordinated with industrial organizations such as the BioAPI Consortium, the X9F4 Working Group, the International Biometric Industry Association, and the Interfaces Group of TeleTrusT. Harmonization of the data structures defined in the original version of CBEFF, ANSI standard X9.84 and the BioAPI specification (which was approved as an ANSI/INCITS standard in February 2002, ANSI/INCITS 358) was addressed. Participation of the International Biometric Industry Association (IBIA) as the Registration Authority for the biometric data format contained in the CBEFF structure was also addressed. The original CBEFF reflected the result of these harmonization efforts. Further CBEFF development was undertaken under the umbrella of the Biometrics Interoperability, Performance, and Assurance Working Group co-sponsored by NIST and the Biometric Consortium.

原本 PDF p.6

CBEFF の初期の概念的定義は、1999 年 5 月 10 日、9 月 17 日、12 月 1 日に、米国国立標準技術研究所と Biometric Consortium が共同後援した 3 回のワークショップを通じて策定されました。これらのワークショップの結果として組織された Technical Development Team が、CBEFF の当初の版（NISTIR 6529）を策定しました。生体データ構造が他の生体認証標準の取り組みと整合するようにするため、策定は、BioAPI Consortium、X9F4 Working Group、International Biometric Industry Association、TeleTrusT の Interfaces Group などの業界団体と調整して行われました。CBEFF の当初の版、ANSI 標準 X9.84、BioAPI 仕様（2002 年 2 月に ANSI/INCITS 標準 ANSI/INCITS 358 として承認）で定義されるデータ構造の調和が図られました。CBEFF 構造に含まれる生体データ形式の登録機関（Registration Authority）として International Biometric Industry Association（IBIA）が参加することも取り上げられました。当初の CBEFF は、これらの調和の取り組みの結果を反映していました。その後の CBEFF の策定は、NIST と Biometric Consortium が共同で後援する Biometrics Interoperability, Performance, and Assurance Working Group の下で進められました。

With the establishment of ISO/IEC JTC 1 SC 37, Biometrics, in 2002, there is now an international standards body focused on the field of biometrics. The United States National Body to JTC1 SC37, the InterNational Committee for Information Technology Standards (INCITS) M1 – Biometrics offered a draft version of NISTIR 6529-A as a contribution to JTC1 SC 37 for consideration as an international standard. A new project for the development of the international version of CBEFF was approved in March 2003. This international version is under development in the Technical Interfaces Working Group of JTC1 SC37. 概要

The Common Biometric Exchange Formats Framework (CBEFF) describes a set of data elements necessary to support biometric technologies in a common way. These data elements can be placed in a single file used to exchange biometric information between different system components or between systems. The result promotes interoperability of biometric-based application programs and systems developed by different vendors by allowing biometric data interchange. This specification is a revised (and augmented) version of the original CBEFF, the Common Biometric Exchange File Format, published as NISTIR 6529. In addition to the name change, which reflects more accurately the scope of the specification, NISTIR 6529-A incorporates new features such as a CBEFF nested structure in order to support multiple biometric data types (e.g., finger, face and voice) and/or multiple biometric data blocks of the same biometric type (e.g., finger biometric data blocks from more than one finger) within a CBEFF data structure, a Biometric Feature to further define the type of biometric data being placed in the file, a Validity Period for that data, an expanded definition of the Creator field which now specifies a Product Identifier, and Index Field associated with a specific instance of biometric reference data, a Challenge-Response field and a Payload field. NISTIR 6529-A also defines two new CBEFF Formats, biometric data objects for use within smart cards and other tokens and a simple root header for use in domains where more than one Patron Format, simple or nested, may be encountered.

The Common Biometric Exchange Formats Framework promotes interoperability of biometric-based application programs and systems. CBEFF defines a set of data elements for use in biometric record headers that supports the interchange of biometric data. CBEFF defines a publicly available process by which any public or private organization can formally register specified file formats using some or all of these data elements. CBEFF defines header fields that can be assembled into a specific biometric data format structure and it defines the logical content of those fields. It defines the concept of a “Domain of Use” to establish the applicability of a standard or specification that meets CBEFF requirements, and a process by which organizations can create formats that meet these requirements. CBEFF requires these organizations to define a format and its data encoding. Adoption of CBEFF compliant Format Specifications promotes interoperability of biometric-based implementations developed by different vendors by allowing biometric data interchange via a standard mechanism.

6. CBEFF Patrons and Clients

原本 PDF p.25

6. CBEFF Patron と Client

6.1 General

原本 PDF p.25

6.1 一般

A CBEFF Patron is an organization that has defined a Format Specification incorporating biometric data objects that comply with CBEFF requirements. Patron define Domains of Use (the context in which a format should be used). It is intended that there be a limited number of Format Specifications with a minimum of overlap in the areas (Domains) where the data is used. However, as new technologies and applications for biometrics emerge, new Patrons and requirements for new Formats will emerge. Each CBEFF Patron can define as many Patron Format Specifications as it requires for its Domains of Use.

原本 PDF p.25

CBEFF Patron は、CBEFF の要件に適合する生体データオブジェクトを取り入れた Format Specification を定義した組織です。Patron は、Domain of Use（形式を使うべき文脈）を定義します。データが使われる分野（Domain）における重複が最小限である、限られた数の Format Specification となることが意図されています。ただし、生体認証の新しい技術とアプリケーションが生まれるにつれて、新しい Patron と、新しい Format の要件が生まれます。各 CBEFF Patron は、その Domain of Use に必要なだけ多くの Patron Format Specification を定義できます。

A CBEFF Client is an entity that creates a specific biometric data structure (a CBEFF client is therefore a BDB format owner) that complies with CBEFF requirements. This would include any vendor, standards body, working group, or industry consortium that has registered itself with IBIA and has defined one or more BDB format types.

原本 PDF p.25

CBEFF Client は、CBEFF の要件に適合する特定の生体データ構造を作成する主体です（したがって、CBEFF Client は BDB Format Owner です）。IBIA に自らを登録し、1 つ以上の BDB の Format Type を定義した、あらゆるベンダー、標準化団体、ワーキンググループ、業界コンソーシアムが含まれます。

Annex E (Informative) Example of CBEFF Utilization Across Domains of Use

原本 PDF p.38

附属書 E（参考）Domain of Use をまたぐ CBEFF の利用例

Described below is the utilization of CBEFF in a government or private organization that has different biometric enrollment applications for its employees and customers.

原本 PDF p.38

以下では、従業員と顧客のために異なる生体登録アプリケーションを持つ、政府機関または民間組織における CBEFF の利用を説明します。

This application, uses BSPs (Biometric Service Providers, the biometric technology modules provided by biometrics vendors) that produce CBEFF-compliant biometric records that also comply with the BioAPI Patron Format. This organization provides its customers with biometric credentials to use in a public, CBEFF-compliant, national or world-wide applications that are also supported by many other organizations. The group of organizations that defined this application can specify and register its own CBEFF-compliant Patron Format that supports its particular Domain of Use.

原本 PDF p.38

このアプリケーションは、BioAPI Patron Format にも準拠する、CBEFF に準拠した生体レコードを生成する BSP（Biometric Service Provider、生体認証ベンダーが提供する生体認証技術モジュール）を使います。この組織は、顧客に、他の多くの組織も支援している、公開された CBEFF 準拠の、国内または世界規模のアプリケーションで使うための生体認証クレデンシャルを提供します。このアプリケーションを定義した組織のグループは、その特定の Domain of Use を支援する、CBEFF に準拠した独自の Patron Format を規定し、登録できます。

The organization in this example must translate its customers’ BioAPI-formatted data into the format of their Domain of Use. It does this through a “Transforming Application” The Transforming Application creates a new record that is compliant with the target Patron Format by mapping the values of the CBEFF fields that both Formats have in common, and by inserting appropriate values into fields that exist only in the target Format. (This could also mean that the Transforming Application must decrypt the BDB (Biometric Data Block -, the biometric data that is normally understood only within a BSP) from the initial record and re-encrypt it into the target record if the two Patron Formats specify different encryption techniques.

原本 PDF p.38

この例の組織は、顧客の BioAPI 形式のデータを、その Domain of Use の形式に変換しなければなりません。これは「Transforming Application」を通じて行います。Transforming Application は、両方の Format に共通する CBEFF フィールドの値を対応付け、対象の Format にのみ存在するフィールドに適切な値を挿入することで、対象の Patron Format に準拠する新しいレコードを作成します。（これは、2 つの Patron Format が異なる暗号技術を規定している場合、Transforming Application が、初期のレコードから BDB（Biometric Data Block、通常は BSP 内でのみ理解される生体データ）を復号し、対象のレコードに再暗号化しなければならないことも意味する場合があります。）

The organization must also translate its employees’ BioAPI-formatted data into the organization’s internal Domain of Use, where it has specified a CBEFF-compliant Format, but has elected not to register this Format for public use.

原本 PDF p.38

この組織はまた、従業員の BioAPI 形式のデータを、組織の内部の Domain of Use に変換しなければなりません。そこでは、CBEFF に準拠した Format を規定していますが、この Format を一般向けに登録しないことを選んでいます。

This example illustrates that the same BDB content can exist and be utilized in different CBEFF-compliant formats as required by different Domains of Use, so that applications within each Domain of Use can recognize and process that content regardless of the Domain of Use where it was created.

原本 PDF p.38

この例は、同じ BDB の内容が、異なる Domain of Use が必要とする、異なる CBEFF 準拠の形式で存在し、利用できることを示しています。これにより、各 Domain of Use 内のアプリケーションは、その内容が作成された Domain of Use にかかわらず、その内容を認識し、処理できます。
