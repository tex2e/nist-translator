# SP 800 資料の抽出レイアウト監査

監査日: 2026-10-03

## 対象と確認方法

- `data/*-trans.json` の196資料を対象とした。うち190資料はPDF、6資料はHTMLソースである。
- 190件すべてについてローカルPDFとJSON内の `source_sha256` を照合し、一致を確認した。
- PDFの全14,800ページを対象に、抽出警告、ページ座標、ページをまたぐ参照、テキストカバレッジを機械走査した。文字カバレッジが低い候補は400ページ・111資料で、[ページ別一覧](page-coverage-candidates.json)に記録した。
- 全資料の抽出ブロックは205,584件。ページ参照が物理ページをまたぐブロックは修正後で2,117件あり、正常な段落継続も含む。
- PDF抽出状態は1,972ブロックが `verified`、195,377ブロックが `needs_review`。`needs_review` は未照合を示し、誤りが確定した数ではない。
- 代表候補ページの原本を目視し、段組の交錯、欄外文字の混入、表セルの断片化、図の欠落を確認した。警告候補をすべて目視検証した状態ではない。
- HTMLソース6資料はPDFの段組・ページまたぎ監査の対象外。
- カバレッジ候補はPDF側のページ文字数に対する抽出ブロックの単語一致率が0.72未満（PDF側25語以上）のページである。ページ番号・定型フッター、図表内文字、数式、目次も差分になるため、400件すべてを誤抽出と確定したわけではない。読み順だけが崩れたページはこの指標で検出できない。

## 原本で確認した未修正の高リスク箇所

以下は抽出漏れ・読み順・対応関係の問題であり、機械的な並べ替えや訳文だけの修正では正しく直せない。ページ番号はPDFの物理ページ。

### 段組・欄外・コールアウト

- SP 800-100 pp.88–89: Recovery Strategy Tipのコールアウト文と本文が交互に混ざる。
- SP 800-12 Rev. 1 p.94: 用語集の左右段で用語・定義の読み順が混ざる。
- SP 800-94 pp.125–126: 索引の左右段が交錯し、別項目が同一ブロックに連結される。
- SP 800-165: 少なくとも23ページで段組の交錯候補。pp.47、51、59などで右段の文が左段見出しより先に出る。
- SP 800-170: 少なくとも45ページで段組の交錯候補。pp.14、45などで本文と右段の箇条書きが同じブロックに混ざる。
- 年次報告書では同種の候補が広範囲にある。SP 800-176は74ページ・234ブロック、182は76ページ・249ブロック、195は111ページ・396ブロック、203は133ページ・395ブロックで段組交錯候補が出ている。これは候補件数であり、全件が目視で誤りと確定した数ではない。
- SP 800-100 p.91など、2段配置でも正常な箇条書き・ぶら下げインデントがある。座標だけで左右段を一括ソートしてはならない。

### 表・数式

- SP 800-81 Rev. 3 p.31およびp.41: 表がparagraphブロックへ分割され、見出し・値・行列の対応が失われる。p.41のTrust anchor selection表では「Could Validate」と値が連結されている。
- SP 800-119 p.55: Table 3-7の列見出し、許可記号、メッセージ名が別々のブロックに分かれ、対応関係を復元できない。
- SP 800-90C p.68: (2^{17}) が `217` と抽出される。
- SP 800-90C p.157: 用語集の一部が段組混線し、`physical noise source` の説明が `pAh nyosiiscea...` のように破損している。
- SP 800-218A p.16: 重複セル断片6件は非表示化済み。親表自体の行列構造は別途原本との照合が必要。

### 図・図中文字

- 図またはグラフ領域が通常の本文抽出に現れない候補: SP 800-176 p.18、182 p.29、192 p.17、195 p.20、203 p.34、207A p.23、226 p.43。
- SP 800-226 pp.15、25: ピラミッド図・矢印図のラベルが断片化し、図中の関係が抽出結果から分からない。
- 図のキャプションがあるだけでは図自体の抽出を保証しない。原本画像がサイトに保持されているかも別途確認が必要。

### 文字欠落・OCR

- SP 800-177 Rev. 1 p.4: 原本が “The” / “This” の箇所で置換文字 `�` が出る。同資料全体で置換文字427個を検出。
- SP 800-225 p.2: 著者・所属の行が交錯。p.11では画像クレジットが本文に混ざる。
- SP 800-229 p.4、SP 800-232 p.12: 単語間スペース欠落。
- SP 800-231 p.5: 目次の語間スペース・文字欠落。
- SP 800-188 p.42: OCRで文字が二重化した長い語を検出。

## 全体の残件

- 既存抽出警告は1,018件、102資料に記録されている。大半は段組の可能性を示す警告で、警告数は確定した不具合件数ではない。
- PDFブロックの大半は `extraction_status=needs_review` のままで、翻訳の前提となる英文抽出を全段落で目視検証済みという状態ではない。
- 単語カバレッジ候補の多い資料はSP 800-156（18ページ）、231（18ページ）、137A（16ページ）、144（15ページ）、87 Rev. 2（13ページ）、53A Rev. 5（12ページ）、53 Rev. 5（12ページ）、126 Rev. 3（11ページ）、84（10ページ）、126 Rev. 2（9ページ）である。ページ別一覧には比較用の抽出テキスト抜粋を含めた。

## 追記: 自動照合による verified 昇格（2026-10-04）

上の本文は全体監査時点のスナップショットで、`verified` / `needs_review` の件数は以後の作業で変わっている。この節が現在値である。

### 現在値

- PDF由来190資料・194,980ブロックのうち、`verified` は50,413、`needs_review` は144,567。
- `verified` のうち30,181ブロックは `scripts/verify_extraction.py` による自動照合で昇格したもので、`extraction_check: "pdfium+ocr"` を持つ。残りは目視照合による。
- 未照合ブロックが残る資料は124件のままである。表・図・脚注・ページまたぎを自動照合の対象外にしているため、全件が `verified` になった資料は増えていない。

### 昇格の条件

次のすべてを満たすブロックだけを昇格させた。1つでも外れたものは `needs_review` のままである。

1. ローカルPDFのSHA-256とページ数がJSONの記録と一致する。
2. 抽出に使った pdfplumber とは別のエンジン（PDFium）で同じ領域を読み直し、正規化後の本文が完全に一致する。
3. 種別が段落・見出し・箇条書き・注記で、参照領域が1ページ内の1つだけである。
4. 二段組警告、低カバレッジ候補、スキャン画像、回転のあるページではない。
5. 同じ行に並ぶ別のテキストや別ブロック、罫線・図形・画像の重なりがない。
6. 数式記号、上付き・下付き、文字サイズの混在、私用領域や置換文字がない。
7. 行末で分割された語を含まない。行末がハイフンで終わる行と、PDFiumが分割語を連結した印（U+0002）の両方を見る。複合語と行分割を機械的に区別できないためである。
8. 断片でも結合でもない。文頭が大文字・数字で始まり、段落は終止の句読点で終わり、前後のブロックと行間・書体から見て同じ文や見出しの続きではなく、ブロック内の行間が均一である。
9. ページを200 dpiで画像化して tesseract でOCRした結果と、英数字列が93%以上（20文字未満は80%以上）一致する。

### 検証

- 前任の目視照合で保留された208ブロック（SP 800-89、147B、201）を同じ規則にかけ、1件も通過しないことを確認した。目視で `verified` とされた2,120ブロックの通過率は約31%で、規則は保守側に寄っている。
- 昇格分から無作為に42ブロックを抜き取り、原本ページの画像と目視で照合した。2件の問題を見つけ、いずれも規則を追加して全件を再判定した。
  - SP 800-195: 2行に割れた大きな見出しの後半だけが通過していた。同じ書体の行が隣接する見出しを保留にした。
  - SP 800-226: 行末のハイフネーションが「pub‐ lication」として残っていた。行末ハイフンを含むブロックを保留にした。
- 規則追加後の抜き取り16件は、文字・範囲ともすべて原本と一致した。
- その後、翻訳レビューの抜き取り中に SP 800-227 で「require-ments」を見つけた。PDFiumが分割語を連結して U+0002 を置く形を、行末ハイフンの規則が見ていなかった。規則を直して全件を再判定し、行末分割による保留は583件から3,478件になった。この修正後の昇格分は、原本画像との目視抜き取りをまだ行っていない。

### 限界

- 自動照合は文字列と範囲の一致を確認するもので、目視照合の代わりではない。規則が見落とす種類の誤りが残っている可能性がある。実際に、抜き取りのたびに新しい種類の見落としが1件ずつ見つかっている。
- 二段組の年次報告書（SP 800-165、170、176、182、195、203）はほとんど昇格していない。これらは読み順の目視照合が必要である。
- 表・図・脚注・数式・ページまたぎのブロックは、すべて目視照合の対象として残っている。

## 追記: 翻訳レビュー（2026-10-04）

英文が確定しているブロック（HTML由来の全ブロックと、PDF由来で `extraction_status=verified` のブロック）の下書き訳を、サブエージェントでレビューした。手順は `scripts/translation_review.py` にある。

### 方法

- 約40ブロックずつのバッチに分け、1バッチを1エージェントが英日を突き合わせて `ok` / `issue` を判定した。`issue` には理由と修正案を付けさせた。
- `ok` のブロックは `status: reviewed` にし、`translation_check: "claude-review"` を付けた。ページ上の「未レビュー訳」が消える。
- `issue` のブロックは修正案を訳文に入れ、下書きのまま残した。修正案がHTML構造か要求語（SHALL など）の数を崩している場合は採用しなかった。
- 修正を入れたブロックは、別のエージェントがゼロから再レビューした。`ok` になったものだけを消し込んだ。
- 修正を2回入れても合意しないブロックは、下書きのまま `translation_check: "claude-issue"` を付けて残した。
- レビュー担当は、最初の約420バッチが既定モデル、以降は Sonnet である。

### 結果

| | ブロック数 |
|---|---:|
| レビューで消し込み（`claude-review`） | 55,304 |
| 　うち修正案を入れてから再レビューで通ったもの | 9,354 |
| 要人手として下書きのまま（`claude-issue`） | 398 |
| 英文が確定していて未レビューの下書き | 0 |

- 再生成後の全ページに残る「未レビュー訳」は135,015件で、作業前の191,431件から減った。残りはほぼすべて、英文が `needs_review` のブロックの訳である。
- 抽出の再判定で英文が `needs_review` に戻った744ブロックは、訳の消し込みを取り消して下書きに戻した。
- 指摘の履歴（資料・ブロックID・回・理由・処置）は `reports/translation-review-issues.json` にある。修正前の訳文はgitの履歴で追える。

### 検証と限界

- パイロットで、81ブロックを1バッチにした緩い指示では、置換の向きが逆の誤訳2件を見逃した。約40ブロック単位で、関係の向き・否定・修飾範囲・要求語の強さを明示した指示に変えて検出できることを確認し、全体はこの方式で流した。
- Sonnet が `ok` としたブロックから12件を抜き取って英日を読み比べた。意味の誤りは0件だった。小文字の may / should / can を「（may）」のように括弧書きで残す訳が2件あり、意味は合っているが体裁として甘い判定である。
- 抜き取りは55,304件に対して12件であり、`ok` 判定の見逃し率を保証する規模ではない。`reviewed` は「機械レビューで問題が見つからなかった」という意味で、人手による校閲済みを意味しない。
- 表紙の題名など、英文そのものがレイアウトで断片化しているブロックは、訳の良否を判定できないことがある。レビュー担当にはその場合 `issue` とするよう指示した。
